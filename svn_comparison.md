# Git vs SVN — ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто маленький файл-указатель (40 байт) с хешем коммита,
на который она смотрит. Создание ветки не копирует файлы и происходит мгновенно
и локально, потому что вся история проекта уже лежит у меня на диске.
Переключение между ветками и слияние — обычные локальные операции.

В SVN всё завязано на центральный сервер. Ветка по соглашению — это копия целого
каталога проекта в папке `/branches` на сервере. Даже если сервер делает
«дешёвую» копию (copy-on-write), любая работа с ветками идёт через сеть, а
слияние исторически было болезненным: до версии 1.5 SVN вообще не хранил
информацию о merge. Поэтому команды часто избегали ветвления — оно требовало
обращения к серверу и ручного разбора конфликтов.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система контроля версий, и единственный источник
истины — это сервер. Команда `svn commit` сразу отправляет изменения на сервер и
требует соединения. Локально у меня лежит только рабочая копия и служебные
метаданные, но нет полной истории репозитория.

Без сети в SVN можно редактировать файлы, посмотреть diff относительно базовой
ревизии и откатить локальные правки (`svn revert`), но зафиксировать новую
ревизию нельзя.

В Git наоборот: `commit` полностью локальный, а интернет нужен только для
`push`, `pull`, `fetch` и `clone`. Можно спокойно коммитить в самолёте, а
синхронизировать позже.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Большие бинарные файлы и медиа** (игры, видео, CAD, дизайн). SVN умеет
  выгружать отдельные папки (sparse checkout) и не заставляет тянуть всю историю,
  как это делает `git clone`.
- **Строгий централизованный контроль доступа.** В SVN есть авторизация по путям
  (path-based access): можно дать доступ к конкретной папке, а не ко всему репо.
- **Блокировка файлов (`svn lock`).** Для несливаемых бинарников эксклюзивная
  блокировка спасает от конфликтов, когда автоматический merge невозможен.
- **Простая линейная история** с последовательными номерами ревизий (1, 2, 3…),
  что удобнее для аудита, чем хеши в Git.
- **Legacy-инфраструктура.** В крупных компаниях, где всё уже построено вокруг
  SVN, миграция дороже, чем поддержка существующего процесса.
